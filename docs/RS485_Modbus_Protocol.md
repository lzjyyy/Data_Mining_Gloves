# 文档说明

本文档描述当前固件的 RS485 通信行为、寄存器映射及双手共线时的配置方法。协议以 Modbus RTU 为基础，所有数值均以十六进制表示，除非另有说明。

实现依据：`UserCode/Lib/rs485_protocol.c`、`UserCode/Lib/rs485_handlers.c`、`UserCode/Tasks/Rs485RecvTask.c` 和 `UserCode/Tasks/StoreTask.c`。

> 注意：本文以当前固件实现为准。读取保持寄存器（功能码 `0x03`）的正常响应含有设备扩展字段，见第 5 章；上位机必须按本协议解析，不能假设它是纯标准 Modbus `0x03` 响应。

# 物理层与总线规则

| 项目 | 规定 |
| --- | --- |
| 物理接口 | RS485，半双工 |
| 串口格式 | 8 数据位、无校验、1 停止位（8N1） |
| 默认从站地址 | `0xC8`（十进制 200） |
| 默认波特率 | 115200 bit/s |
| 通信模式 | 主站请求、从站响应；主站必须逐帧等待响应或超时 |
| CRC | Modbus CRC-16，初值 `0xFFFF`，多项式 `0xA001`，帧尾低字节在前 |

两只手接到同一 USB-RS485 转换器时，必须使用不同的从站地址。主站一次只能轮询一个从站，不能向同一地址连接两只手。

## 地址与静默规则

从站合法地址范围为 `0x01` 到 `0xF7`（十进制 1 到 247）。地址 `0x00` 是广播地址。

| 收到的帧 | 从站行为 |
| --- | --- |
| 地址不是本机地址 | 静默，不回复 |
| 广播地址 `0x00` | 静默，不回复 |
| 帧长度不足、噪声帧 | 静默，不回复 |
| CRC 错误 | 静默，不回复 |
| 本机地址且 CRC 正确 | 执行功能码处理，正常响应或异常响应 |

广播帧不用于读取、地址发现或配置确认。若不知道设备地址，必须先只连接一只手，再使用默认地址或已知地址读取和配置；不能通过广播查询地址。

# 通用帧格式

## 请求帧

```text
+---------+---------+----------------------+---------+---------+
| 地址    | 功能码  | 功能码相关数据       | CRC Lo  | CRC Hi  |
+---------+---------+----------------------+---------+---------+
| 1 byte  | 1 byte  | N bytes              | 1 byte  | 1 byte  |
+---------+---------+----------------------+---------+---------+
```

寄存器地址、寄存器数量和 16 位整型数据均为大端序（高字节在前）。CRC 附加顺序为低字节、再高字节。

## 标准异常响应

仅当请求满足“本机地址 + CRC 正确”时，设备才可能回复异常帧：

```text
+---------+---------------+---------+---------+---------+
| 地址    | 功能码 | 0x80 | 异常码  | CRC Lo  | CRC Hi  |
+---------+---------------+---------+---------+---------+
| 1 byte  | 1 byte         | 1 byte  | 1 byte  | 1 byte  |
+---------+---------------+---------+---------+---------+
```

| 异常码 | 含义 | 典型触发条件 |
| --- | --- | --- |
| `0x01` | 非法功能码 | 本机地址、CRC 正确，但功能码未注册 |
| `0x02` | 非法数据地址 | 寄存器起始地址不支持 |
| `0x03` | 非法数据值 | 数量、字节数、地址值或波特率编码不合法 |
| `0x04` | 从站设备故障 | 内部处理失败 |

# 寄存器表

| 地址 | 名称 | 访问 | 数据类型 / 数量 | 说明 |
| --- | --- | --- | --- | --- |
| `0x0000` | 从站地址 | 读 / 写 | `uint16`，低 8 位有效 | 合法值 `0x0001` 到 `0x00F7` |
| `0x0001` | 波特率编码 | 读 / 写 | `uint16` | 编码见表 2 |
| `0x0002` - `0x0007` | 目标位置 | 写 | 6 个 IEEE 754 binary16 | 通过 `0x10` 与目标速度一起写入 |
| `0x0008` - `0x000D` | 目标速度 | 写 | 6 个 IEEE 754 binary16 | 通过 `0x10` 与目标位置一起写入 |
| `0x000E` - `0x0013` | 位置反馈 | 读 | 最多 6 个 IEEE 754 binary16 | 用户侧角度 |
| `0x0014` - `0x0019` | 速度反馈 | 读 | 最多 6 个 IEEE 754 binary16 | 角速度 |
| `0x001A` - `0x001F` | 电流反馈 | 读 | 最多 6 个 IEEE 754 binary16 | 已换算的实际电流 |
| `0x0100` | OTA 标志 | 写 | 2 个寄存器 | 进入 OTA / Boot 流程 |
| `0x0A00` | 复位命令 | 写 | `uint16` | 通过 `0x06` 触发复位流程 |
| `0x0B00` - `0x0B04` | 固件版本 | 读 | 5 个 `uint16` | 主版本、次版本、修订号、发布日期高 16 位、低 16 位 |

表 2：波特率编码。

| 编码 | 波特率（bit/s） |
| --- | ---: |
| `0x0001` | 9600 |
| `0x0002` | 19200 |
| `0x0003` | 38400 |
| `0x0004` | 57600 |
| `0x0005` | 115200 |
| `0x0006` | 230400 |
| `0x0007` | 460800 |
| `0x0008` | 921600 |

binary16 数据为 IEEE 754 半精度浮点数，每个寄存器占 2 字节，高字节在前。

# 功能码 `0x03`：读取保持寄存器

## 请求格式

```text
+---------+---------+----------+----------+--------+--------+---------+---------+
| 地址    | 0x03    | 起始 Hi  | 起始 Lo  | 数量 Hi| 数量 Lo| CRC Lo  | CRC Hi  |
+---------+---------+----------+----------+--------+--------+---------+---------+
```

请求总长度必须为 8 字节。对 `0x0000`（系统配置）必须读取 2 个寄存器；对 `0x0B00`（版本）必须读取 5 个寄存器；对每段反馈寄存器可读取 1 到 6 个寄存器。

## 当前固件响应格式

当前固件的 `0x03` 正常响应为下列设备扩展格式：

| 字节位置 | 字段 |
| --- | --- |
| 1 - 2 | 地址，`0x03` |
| 3 - 4 | 请求的起始地址，高字节在前 |
| 5 - 6 | 请求的寄存器数量，高字节在前 |
| 7 | 数据字节数 |
| 8 - (7 + 数据字节数) | 数据 |
| 最后 2 字节 | CRC Lo，CRC Hi |

其中 `字节数 = 数量 x 2`。该响应比标准 Modbus RTU `0x03` 响应多了“起始地址”和“数量”4 个字节。标准 Modbus 客户端如不支持这一扩展，必须在上位机侧按本表自定义解析。

## 读取地址和波特率

读取系统配置必须使用设备当前的单播地址，不能使用广播地址。

```text
请求（默认地址 0xC8）：C8 03 00 00 00 02 D5 92
响应（地址 0xC8、115200）：C8 03 00 00 00 02 04 00 C8 00 05 91 57
```

响应数据的第一个寄存器为当前从站地址，第二个寄存器为波特率编码。上例中的 `00 C8` 表示地址 `0xC8`，`00 05` 表示 115200 bit/s。

# 功能码 `0x06`：写单个寄存器

## 请求与响应格式

```text
+---------+---------+----------+----------+----------+----------+---------+---------+
| 地址    | 0x06    | 寄存器 Hi| 寄存器 Lo| 数值 Hi  | 数值 Lo  | CRC Lo  | CRC Hi  |
+---------+---------+----------+----------+----------+----------+---------+---------+
```

正常响应与请求中 CRC 之前的 6 个字节相同。当前固件支持写入 `0x0000`、`0x0001` 和 `0x0A00`；其他地址回复异常码 `0x02`。

## 修改从站地址

地址值只使用低 8 位，合法范围为 1 到 247。修改地址的响应仍使用旧地址发送；响应完成后，设备立即按新地址接收后续请求，并通过存储任务写入 EEPROM。

```text
将默认地址 0xC8 改为 0xC9：
请求：C8 06 00 00 00 C9 58 05
响应：C8 06 00 00 00 C9 58 05

随后读取新地址：
请求：C9 03 00 00 00 02 D4 43
响应：C9 03 00 00 00 02 04 00 C9 00 05 C4 6B
```

## 修改波特率

向 `0x0001` 写入表 2 中的波特率编码。设备先以旧波特率发送 `0x06` 正常响应，确认发送完成后才重初始化串口至新波特率。因此主站应先接收完整响应，再切换本机波特率。

地址和波特率的 EEPROM 保存由后台存储任务执行，协议没有单独的“保存完成”响应。完成配置后不要立刻断电。

# 功能码 `0x10`：写多个寄存器

## 请求格式

| 字节位置 | 字段 |
| --- | --- |
| 1 - 2 | 地址，`0x10` |
| 3 - 4 | 起始地址，高字节在前 |
| 5 - 6 | 寄存器数量，高字节在前 |
| 7 | 数据字节数 |
| 8 - (7 + 数据字节数) | 写入数据 |
| 最后 2 字节 | CRC Lo，CRC Hi |

请求总长度必须严格等于 `9 + 字节数`，且 `字节数 = 数量 x 2`。

## 位置与速度命令

控制命令的起始地址必须为 `0x0002`，数量必须为 12，字节数必须为 24：前 6 个 binary16 为目标位置，后 6 个 binary16 为目标速度。

正常响应采用标准 `0x10` 响应：

```text
+---------+---------+----------+----------+--------+--------+---------+---------+
| 地址    | 0x10    | 起始 Hi  | 起始 Lo  | 数量 Hi| 数量 Lo| CRC Lo  | CRC Hi  |
+---------+---------+----------+----------+--------+--------+---------+---------+
```

## OTA 标志

向 `0x0100` 写入 2 个寄存器（4 字节）触发 OTA / Boot 流程。当前固件的该正常响应为设备扩展格式：地址、功能码、起始地址、数量、字节数 `0x04`、固定数据 `12 34 56 78` 和 CRC。上位机应将其视为 OTA 专用响应。

# 双手共线配置步骤

1. 只连接第一只手，主站设置为默认波特率 115200，使用默认地址 `0xC8` 读取系统配置。
2. 使用 `0x06` 将第一只手改为唯一地址，例如 `0xC9`；确认响应后，用新地址读取 `0x0000` 和 `0x0001`。
3. 断开第一只手，只连接第二只手。若第二只手仍为默认地址 `0xC8`，重复读取与改址流程，例如改为 `0xCA`。
4. 两只手都配置完成后再并联到同一 RS485 总线。主站依次轮询 `0xC9`、`0xCA`，每次只等待被寻址设备的响应。
5. 修改波特率时，必须在总线上所有设备使用同一波特率。建议逐台单独连接并修改，再将主站和所有设备切换到目标波特率。

若两只手保持相同地址并同时接入总线，它们会同时响应同一请求，导致 RS485 数据冲突；此状态无法通过广播查询解决。

# 上位机处理建议

* 仅对单播、CRC 正确的请求等待响应；超时应按“无响应”处理，不能期待 CRC 错或地址错误会返回错误码。
* 收到功能码最高位为 1 的响应时，读取第 3 字节作为异常码。
* 收到 `0x03` 正常响应时，先读取返回的起始地址、数量和字节数，再解析数据。
* 修改从站地址后，下一帧立即使用新地址；修改波特率后，先等旧波特率下的响应完整发送，再切换主站波特率。
* 配置两只新设备时始终一次只接入一只，避免默认地址 `0xC8` 冲突。
